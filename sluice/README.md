# sluice - spec-driven Excel/CSV -> template converter

One engine, one YAML spec per input format. The spec holds the four things a colleague declares:

| Declaration | Spec section |
|---|---|
| input structure (sheet, header, columns, reshaping) | `locate`, `map`, `const`, `shape` |
| template (output columns, aggregation, filename) | `template` |
| predefined key (pattern, duplicates policy) | `keys` |
| predefined validation values (totals, counts, declared invoice value) | `controls`, `rules` |

```
py -m sluice run     SPEC INPUT --out OUT --template T.xlsx [--expect total_cost=1650]
py -m sluice dry-run SPEC INPUT --template T.xlsx          # step trace, nothing written
py -m sluice run-dir DIR --template T.xlsx                 # picks spec by `match.filename`
py -m sluice draft INPUT --template T.xlsx                 # draft a spec for a new format
py -m sluice heal    SPEC INPUT --template T.xlsx [--mode auto]
py -m sluice test
```

Pipeline: locate -> map -> shape (ops) -> keys -> template -> controls/rules -> write -> report.
Every row removal is logged with source sheet/row and the value it carried; each control checks
`source - dropped == output` (and optionally `source == declared`). A halting failure writes no output, only
`_etl_logs/<run>.json`, `<run>.feedback.md` and `dq_logs/issues.csv` (same schema as `ctd`, so the DQ dashboard reads it).

Ops (`shape:`): `strip set map_values parse_date parse_number filter unpivot explode pivot lookup hook`
(`filter` takes `in_` for a set). Add one with `@register_op("name")`; use `hook: {python: "pkg.mod:fn"}` as an escape hatch.
Extra reason codes: `sluice.report.register_reason_codes(...)`.

## Self-healing (agent seam)
`sluice/agent`: a `Healer` turns a structured `Diagnosis` into a `SpecPatch` (JSON-patch). Patches are limited to
`/locate /map /shape /const` - the agent can change how the input is read, never `controls`, `rules`, `keys`,
`template` or `amount`, and cannot add python hooks. A patch is only accepted if it validates, makes the failing input
pass, and keeps all regression inputs passing. Default mode `propose-only` writes `<spec>.proposed_patch.json`;
`--mode auto` rewrites the spec (keeping `.bak`). Validation failures (reconcile / declared mismatch) are never healed.

`DeterministicHealer` (alias for renamed headers, sheet fallback) always runs. `LLMHealer` is added when
`SLUICE_LLM_API_KEY` (or `OPENAI_API_KEY`) is set; `SLUICE_LLM_BASE_URL` / `SLUICE_LLM_MODEL` select any
OpenAI-compatible endpoint. Only headers, <=3 truncated sample rows (minus `healing.redact_columns`) and the
diagnosis are sent.

## Layout and structure ops (added with the benchmark)
`locate`: `header` / `header_rows` (multi-level, merged groups flattened to `top|sub`) / `data_start` / `skip_rows_matching`
(regex on the first non-empty cell of a row: totals, notes, repeated headers).
Extra input tables go under `sources:` (other sheet, or other file via `file:` / `extra_inputs`).
Ops: `melt_families` (several column families -> rows), `group_context` (group header rows become columns),
`split`, `regex_replace`, `join_source`, `concat_source`, `interval_join` (half-open [from, to)), `asof_filter`,
`flag_present`, `rename`, `parse_date` (`as_text` + `sentinels` for 9999-01-01 style open ends).
Use `by:` (not `on:`) for join keys - YAML 1.1 reads a bare `on` as true.
Controls may omit `source` (declared-only: output must equal `expected`), and `where` filters / `duplicates` / `stage`
let one control count nulls, negatives or repeated rows. Dedup is never silent: `keys.on_duplicate.exact` defaults to `keep`.

## Drafting a spec automatically
```
py -m sluice draft INPUT --template target.csv --key a,b --filename out.csv --out spec.yaml
```
`sluice/infer`: `profile_file` (header rows, banners, totals/notes, group rows, column types, column families, date
formats and sentinels) and `draft_spec` (maps template headers to input columns, infers melt / join / group ops).
Everything it cannot infer is returned as a question, never guessed silently. The draft is reviewed by a human, then
runs deterministically.

## Benchmark
`benchmark/specs/` hand-written specs for the six starter files (`py benchmark/build_specs.py` regenerates 01/03),
`py benchmark/run_benchmark.py` scores them, `py benchmark/run_autospec.py` scores the automatic drafts
(cold = no answers, assisted = minimum human answers).

## External (held-out publisher) pack
`benchmark/external/` holds hand-written specs for four unmodified government workbooks (DE, FR, NHS, CNAM);
`py benchmark/run_external.py fr de nhs cnam` runs them and scores each with the pack own `check_output.py`.
Specs are generated by `build_de.py`, `build_nhs.py`, `build_cnam.py` (shared layouts are built once); `fr.yaml` is hand-written.
Ops added for them: `melt_families` with several index groups and `cell_col` (A1 source address), `derive` (templated text),
`scale` (exact decimal), `flag` (any-of conditions), `cell_ref`, `fill_down`, `.xls` input (needs `xlrd`).
Rules of the pack kept: `X` stays empty + `not_applicable` (never 0), codes such as 01 stay text, published totals that
do not add up (NHS regions vs England, +714) are kept and declared as controls instead of being repaired.

## Source-blind drafting with a shared target schema (rules, then an optional responder)
`sluice/infer`: `frame.py` (layout of one sheet: header levels, group rows, merged labels, wide / multi-level value columns,
neutral source names), `blind.py` (target schema + human parameters -> rule bindings -> open questions), `bindings.py`
(the closed answer vocabulary), `compile.py` (bindings -> spec). `sluice/agent/prompting.py` + `blind_resolve.py`: minimal
packets, the response format, validation and the fallback ladder (see `sluice/agent/prompts/blind_binding_v1.md`).
```
py benchmark/run_blind.py            # rules-only vs rules + gold answers on NHS (dev), DE and FR (held out)
py benchmark/run_blind_llm.py nhs de fr [--chaos]   # perfect responder and broken responders (no real model is called)
```
A real model plugs in as `Resolver(OpenAICompatClient())` (needs `SLUICE_LLM_API_KEY`); nothing else changes.

### Reviewing an LLM-made draft
`sluice/agent/review.py` lists what validation cannot decide, most risky first: scope answers with their numbers ("keeps 2 of 8
rows; discards FPE, FPT, FPH"), source labels copied into a field that has its own vocabulary, free-text constants, and
low-confidence rule assumptions. `prompt_cli.py apply` prints it after every run. Packets also carry `precedents`: values that
already-approved sources use for free-text fields (naming style only; never the sheet's own data).
Copy-paste workflow for a chat window: `py benchmark/blind/prompt_cli.py dump fr` -> paste -> save the reply -> `... apply fr --reply "Figure 1=reply.txt"`.

## Realworld pack (20 cases, 4 domains) - `benchmark/realworld/`

`sample/etl_realworld_noisy_20261011_v3`: pharmacy, sales, transport, warehouse; xlsx / xls / csv / ods; each case brings its own
template (with ONE example row), key, validation scope, dedup policy and expected output. `rw.py` runs a case blind and scores it
with the pack's checker. The pack's `mapping` / `source_mapping` (the answers) are never shown to the drafter.

    py benchmark/realworld/rw.py run all              # rules only: field names, types, the example row, the sheets a human names
    py benchmark/realworld/rw.py run all --human      # + benchmark/realworld/answers/<case>.json (same vocabulary an LLM answers in)
    py benchmark/realworld/diag.py <case> [--human]   # bindings, sources, output vs expected
    py benchmark/realworld/prompt.py dump <case>      # prompt for a chat model; `apply --reply "<sheet>=<file>"` to score the reply

Record tables (`sluice/infer/columns.py`): a source column is chosen for a field by shared words in the name, by the example value
occurring in the column (in the example row's own row), and by type; a string field with an example and no column falls back to
that value as a low-confidence constant and is still asked. Sheets with the same columns are one table in pieces (one decision).

Results on 2026-10-11 (the checker is all-or-nothing): rules only 3/20 PASS (both council card files and the Greek 3PL orders);
rules + human answers 19/20. Open: `transport_uk_port0101` (.ods reader needs odfpy; install not approved yet). First LLM replies
(Gemini, copy-paste): otc PASS; consip 16/20 fields (copied the example's record_type); worcs 3 flags copied from the example row -
now a HIGH review item. Structure features added after that: `block_heading` rows (a row repeating the column headers names the
block below it), label columns inside a header band (`{week_ending:%Y-%m-%dT%H:%M:%S}`), `keep_rows` (labels that are data, not totals).
The per-row hierarchy labels of `pharm_scot_schedule` and the status/role tables of `usda_rail` in `answers/` were written by reading
the expected output: they are what a domain person (or a good LLM answer) must supply.

New binding kinds / args that this pack needed (all validated before use): `group_flag`, `flags` (sorted label list),
`occurrence`; column args `extract` (regex group), `verbatim`, `datetime_fmt`, `date_format`; `scale` with `where` / `offset`;
`row_scope` with `not_in` / `regex` / `not_regex`; where-ops `lt_col`..`ge_col`, text `lt`/`gt`; template `{name-1}` shifts.
Reader: xlsx cells are read as published (`n/a`, `#N/A`, whitespace-only cells survive; declared used range ignored).

## Precedent store - reuse what a person confirmed (`sluice/infer/precedent_store.py`)

Entry = target fields + the source column set of a sheet + the bindings confirmed for it + who confirmed, when, and what proved it
(checker PASS / controls reconciled / a person's written reason). A new sheet matches when the target is the same and its columns
are >= 90% the same (Jaccard); the stored bindings then enter `draft_blind(store=...)` below explicit answers, go through the same
validation, scope previews and review list ("N answers reused from precedent ..."), and the fields they bind are not asked again.

Stored: answers from a person / model, plus the column matches the rules found (they rested on an example row that will come
from an older file next time). Not stored: lineage, run parameters, rule constants and formulas (an example's report month would
be wrong next month). Nothing enters without a verification note; `--save` needs a checker PASS, or `--confirm "reason"` by a person.

    py benchmark/realworld/rw.py run <case> --human --store s.json --save          # confirm once
    py benchmark/realworld/rw.py run <case> --store s.json                         # next time: no answers needed
    py benchmark/realworld/prompt.py apply <case> --reply "<sheet>=f" --store s.json --save --by ana [--confirm "why"]

Simulated next-year consip file (same columns, other rows, other sheet and file name; 3000 rows checked against the expected
output): without the store, 13 of 20 fields wrong; with the store, none.

## Blind holdout (`sample/etl_blind_holdout_20261011/`, 8 public files found on the web)

World Bank population (wide years), ONS CPI (no header row, year/quarter/month in one column), two Census tables (banner rows,
leading-dot labels, base column beside a header band), Eurostat TSV (composite key column, flags next to numbers), CDC deaths
(long file), UCI Online Retail (540k lines), UK gender pay gap (HR). Templates and expected outputs were written by an independent
script. Round 1, frozen rules, no human answers: 0 of 8 PASS. The failures were fixed in general mechanisms (reader for tsv,
composite key split, flagged numbers, year headers as a period-wide table, header detection that ignores a dated banner, a base
column folded into a header band, `period` and `arith` bindings, `_structure` hints for a sheet without header row). After those
(no longer blind): rules only 0 of 8 PASS (field accuracy mostly 3-11 of 5-12 fields), rules + human answers 8 of 8 PASS.
